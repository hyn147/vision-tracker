## 2. 一帧处理流程

按实际执行顺序简述 `onFrame`：

1.定义未接受的旧快照，遍历已观测到的目标，给旧快照中各种变量赋值
2.检查时间戳、负数、同帧重复、类型是否一致，并适时返回旧快照
3.遍历已通过检查的帧中的目标，检查是否出现过，并调用对应函数或创建对象
4.遍历已创建目标，检查哪个目标未被观测并调用对应函数
5.清空res参数，再次遍历已观测目标、更新res并返回
重点说明：整帧校验失败时，为什么不会留下部分修改。
    校验发生在更新armor_target_count等计数之前，若有一项校验未通过，提前返回已经创建好的旧快照，不会继续进行后续修改，不会更新m_targets。而旧快照的创建发生在遍历本帧目标前，本帧不会对旧快照有影响

### 3.2 附加三：静态成员与 static

按照项目 README 中附加三的要求，说明 `static` 的使用位置、用途、选择理由，以及不使用 `static` 时的问题。
    在旋转装甲和普通装甲的丢失阈值设定时使用，用来定义两种类型的丢失阈值，这样可以让语义更清晰，所有同类型装甲共用一个丢失阈值。如果不使用static，每个目标都存放一个丢失阈值，可能造成误解；若直接返回数字，不便于之后阈值可能的更改。
    完成附加一时，将Del_count设为静态成员变量，因为所以目标的删除阈值一致，无需每个目标单独存一份。
### 3.3 附加四：智能指针

按照项目 README 中附加四的要求，说明使用的智能指针类型、使用位置、选择理由和带来的好处；认为不需要智能指针的位置也要说明原因。
    独占指针。指向TrackingBase类的对象（m_targets为独占指针）。
    每个目标单独拥有一份m_id等变量，不需要拷贝赋值，可以用独占指针。
    无需手动释放内存，明确目标的所有权，支持继承和多态。
    不需要智能指针的地方：每一帧的观测数据。这些量不涉及继承或多态，不必要使用智能指针。
